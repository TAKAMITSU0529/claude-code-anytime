# Kindle Highlights App - 要件定義書

## 1. プロジェクト概要

Kindleで読んだ本のハイライト（マーカー）情報を集約・管理し、読書内容の復習を支援するWebアプリケーション。

### 1.1 解決する課題
- Kindleのハイライトが散在しており、振り返りが困難
- 読んだ本の内容を忘れてしまう
- 定期的な復習の仕組みがない

### 1.2 ゴール
- ハイライトを一元管理し、本棚のように視覚的に閲覧できる
- AIによる要約で素早く内容を把握できる
- 定期通知で自然に復習できる習慣を作る

---

## 2. 機能要件

### 2.1 Kindleハイライト集約機能

#### 2.1.1 ハイライトデータの取り込み
- **データソース**: Kindleの「My Clippings.txt」ファイルをアップロードして取り込む
  - Kindle端末をPCに接続すると `documents/My Clippings.txt` に全ハイライトが保存されている
  - このファイルをドラッグ＆ドロップまたはファイル選択でアップロード
- **パース処理**: My Clippings.txt を解析し、以下の情報を抽出する
  - 書籍タイトル
  - 著者名
  - ハイライト箇所のテキスト
  - 位置情報（ロケーション）
  - ハイライト日時
- **重複排除**: 同一ハイライトの重複インポートを防止する

#### 2.1.2 書籍情報の補完
- **表紙画像の取得**: 書籍タイトル・著者名をもとに、外部API（Google Books API / OpenBD API）から表紙画像を自動取得する
- **ジャンル情報**: ユーザーが手動でジャンルタグを設定できる（例: ビジネス、技術、小説、自己啓発など）
- ジャンルはカスタムで追加可能とする

### 2.2 本棚表示機能

#### 2.2.1 本棚ビュー（一覧画面）
- 読んだ本を**表紙画像のグリッド**で表示する
- **ジャンル別フィルタリング**: タブまたはサイドバーでジャンルごとに絞り込み表示
- **並び替え**: 追加日順、タイトル順、ハイライト数順で並び替え可能
- **検索**: 書籍タイトル・著者名でのテキスト検索

#### 2.2.2 書籍詳細画面
- 表紙をクリックすると、その本のハイライト一覧を表示
- ハイライトは位置情報順に表示
- 各ハイライトにメモを追加可能
- ハイライトごとのAI要約を表示（2.3参照）

### 2.3 要約機能

#### 2.3.1 ハイライト要約
- 各ハイライトの内容を**1〜2文に要約**する
- OpenAI API（GPT）を使用して要約を生成
- 要約はハイライト取り込み時に自動生成し、DBに保存する
- ユーザーが手動で再生成をリクエストすることも可能

#### 2.3.2 書籍全体の要約
- 1冊分のハイライトを統合し、その本の要点を要約する（オプション機能）

### 2.4 通知機能

#### 2.4.1 通知チャネル
- **Discord Webhook** を第一候補として実装する
  - 理由: API連携が最もシンプル（Webhook URLを設定するだけ）、無料、Bot申請不要
  - LINE / Slack も将来的に対応可能な設計にする

#### 2.4.2 通知内容
- ランダムに選ばれたハイライト1〜3件を通知
- 通知内容:
  - 書籍タイトル
  - ハイライト本文（長い場合は抜粋）
  - AI要約（1〜2文）
- Embedフォーマットで見やすく表示（Discord）

#### 2.4.3 通知スケジュール
- ユーザーが通知時間を設定可能（例: 毎朝7:00、昼12:00）
- 複数の時間帯を設定可能
- 通知の有効/無効をトグルで切り替え可能
- サーバーサイドのスケジューラー（APScheduler）で実行

## 3. 非機能要件

### 3.1 技術スタック

| レイヤー | 技術 | 理由 |
|---------|------|------|
| フロントエンド | Next.js (React) + TypeScript | モダンなUI構築、SSR対応 |
| UIライブラリ | Tailwind CSS + shadcn/ui | 高速な開発、統一的なデザイン |
| バックエンド | Next.js API Routes | フロント・バックエンドを統合管理 |
| データベース | SQLite (Prisma ORM) | セットアップ不要、軽量、個人利用に最適 |
| AI要約 | OpenAI API (GPT-4o-mini) | コスト効率が良く高品質な要約 |
| 表紙画像取得 | Google Books API | 無料、カバー率が高い |
| 通知 | Discord Webhook | 設定が最もシンプル |
| スケジューラー | node-cron | Node.js環境で完結 |
| デプロイ | ローカル実行 / Vercel | 個人利用を想定 |

### 3.2 パフォーマンス
- 本棚画面のロード: 2秒以内
- ハイライト取り込み: 100件あたり5秒以内（AI要約は非同期処理）

### 3.3 セキュリティ
- APIキー（OpenAI, Discord Webhook URL）はサーバーサイドの環境変数で管理
- ファイルアップロードのバリデーション（拡張子・サイズ制限）

## 4. データモデル

```
Book (書籍)
├── id: string (UUID)
├── title: string (書籍タイトル)
├── author: string (著者名)
├── coverImageUrl: string? (表紙画像URL)
├── genre: string? (ジャンルタグ)
├── createdAt: datetime
└── updatedAt: datetime

Highlight (ハイライト)
├── id: string (UUID)
├── bookId: string (FK → Book)
├── content: string (ハイライト本文)
├── summary: string? (AI要約)
├── location: string? (位置情報)
├── highlightedAt: datetime? (ハイライト日時)
├── memo: string? (ユーザーメモ)
├── createdAt: datetime
└── updatedAt: datetime

NotificationSetting (通知設定)
├── id: string (UUID)
├── webhookUrl: string (Discord Webhook URL)
├── scheduleTimes: string[] (通知時刻リスト, 例: ["07:00", "12:00"])
├── isEnabled: boolean (有効/無効)
├── highlightCount: number (1回の通知で送るハイライト数)
├── createdAt: datetime
└── updatedAt: datetime
```

## 6. API設計

| メソッド | エンドポイント | 説明 |
|---------|--------------|------|
| POST | `/api/import` | My Clippings.txt をアップロード・パース |
| GET | `/api/books` | 書籍一覧取得（ジャンルフィルタ対応） |
| GET | `/api/books/[id]` | 書籍詳細+ハイライト取得 |
| PATCH | `/api/books/[id]` | 書籍情報更新（ジャンル変更等） |
| DELETE | `/api/books/[id]` | 書籍削除 |
| PATCH | `/api/highlights/[id]` | ハイライト更新（メモ追加等） |
| POST | `/api/highlights/[id]/summarize` | 要約を再生成 |
| GET | `/api/settings/notification` | 通知設定取得 |
| PUT | `/api/settings/notification` | 通知設定更新 |
| POST | `/api/notification/test` | テスト通知送信 |

## 9. 前提条件・制約

- ユーザーはKindle端末またはKindleアプリから `My Clippings.txt` を取得できること
- OpenAI APIキーをユーザー自身が取得・設定すること
- Discord Webhook URLをユーザー自身が作成・設定すること
- 個人利用を想定（マルチユーザー認証は対象外）
